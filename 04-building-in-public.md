# 4 · Building in public

Knode is open source and built in public from the first commit: the code, the issues, the
roadmap and the decisions are visible to everyone.

## Public

- All repositories, from creation.
- Issues, pull requests, milestones and discussions.
- The decision log and the roadmap.
- The brand kit, public to read and to contribute to; the brand itself is reserved (Knode Brand License).

## Never in a repository

- Secrets: API keys, tokens, certificates, passwords, signing material. Use the keychain or the CI secret store.
- Personal data, including real AI-conversation exports used for testing. Test files are made by hand or fully anonymised.
- Private conversations with users or partners.

If a secret is pushed by mistake, treat it as leaked: revoke it first, then clean the history.

## Writing in public

Write issues and pull requests so a stranger can follow them. Explain the why, link the context,
and keep the tone of the brand: clear, calm, no hype.
